Workshop purpose and boundaries

The promise

Participants move from customer evidence to a working Copilot Studio prototype in one hour. They learn the process by doing: sign in, upload documents, confirm the MVP, review generated assets, deploy, and test.

What RAPP means in this workshop

RAPP is the guided Documents to Copilot Studio workflow. The broader RAPP platform can translate portable agent logic into multiple Microsoft destinations; this module intentionally focuses on Copilot Studio.

In scope

Use-case evidence that is permitted for Azure OpenAI processing.

A focused MVP with one to four demonstrable capabilities.

Generation of portable agent files and live/demo solution twins.

Import into a workshop environment and test in Copilot Studio.

Evidence capture and a clear next-improvement statement.

Out of scope

Production architecture approval, security sign-off, or go-live authorization.

Large-scale integration design, change management, or operating-model design.

Processing data the customer is not authorized to share.

Direct image uploads in the current workshop uploader; OCR or convert image-only content first.

Rehearsal standard

Rehearsal 1 - technical path (45 minutes)

Use a clean browser session and the same type of participant account.

Upload all three example inputs; confirm the expected MVP.

Generate and inspect capability count, system names, and write intent.

Import live and demo twins sequentially.

Test one happy path, one edge case, and one unknown value.

Export evidence and record elapsed time per step.

PASS CRITERIA All five steps complete in 35 minutes or less, leaving time for narration and participant recovery. No facilitator-only repair is needed.

Rehearsal 2 - facilitation path (60 minutes)

Present the deck aloud with a producer playing a participant.

Use the scripted questions; do not skip the MVP read-aloud.

Practice concise explanations of demo twin, live prototype, connection references, and unpublished import.

Record transitions that exceed 30 seconds and simplify them.

End with a 2-minute participant teach-back.

Rehearsal 3 - contingency path (30 minutes)

Simulate sign-in failure: pair the participant and continue.

Simulate wrong MVP: edit the statement and explain the gate.

Simulate generation failure: use the prebuilt packages and continue the review/deploy story.

Simulate no environment access: demonstrate with the demo twin and capture an access action.

Simulate pending live connections: bind only if safe; otherwise explain the migration step.

Example scenario answer key

Expected MVP

TITLE: Facilities Service Request Assistant Create an assistant for employees to report facilities issues. It collects location, category, and urgency; summarizes the request; answers from approved maintenance guidance; and creates a synthetic service-request receipt for workshop testing.

Expected capabilities

CapabilityEvidenceExpected behavior
Request intakeTranscript asks for location, issue type, urgency.Ask only for missing required fields.
Triage and summaryCoordinator manually classifies and rewrites requests.Classify category/urgency and produce a concise summary.
Guidance answerFAQ contains approved self-service and safety guidance.Answer from approved evidence; escalate when uncertain.
Service-request creationDesired future process creates a record/receipt.Workshop uses a deterministic synthetic receipt; live path remains connector-ready.

Acceptable variation

Three or four capabilities are acceptable if intake and triage are combined.

The title may use "Facilities Intake Copilot" or similar language.

The service-request action may be described as simulated creation, receipt generation, or a connector-ready create action.

The result is not acceptable if it claims a production system was updated during the workshop.

Minimum debrief questions

Which source detail most influenced the generated agent?

What must change before a customer pilot?

Close and follow-up

Same-day close

Store source, confirmed MVP, packages, test evidence, and observations in {ARTIFACT_LOCATION}.

Send the same-day thank-you and pulse survey from the communications pack.

Document the next improvement, owner, and due date.

Do not represent the prototype as production-approved.

T+1 outcome summary

Send a one-page summary with the business problem, confirmed MVP, generated capabilities, environment/publication status, test evidence, known gaps, and recommended decision: iterate, scale, or stop.

T+5 decision checkpoint

Confirm whether the customer will: (1) run a second RAPP iteration, (2) move into integration/implementation planning, or (3) stop because the evidence did not support the use case.
